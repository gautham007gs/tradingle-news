# SEO Audit — 2026-08-24

Compliance check of the public site against the SEO contract in `AGENTS.md` / `SEO_RULES.md`.
Result: **compliant**; two imagery bugs found and fixed (F2/F3, see MASTER §2).

## Rule-by-rule verification

1. **Rendering** — Article pages render headline (`<h1>`), byline, publish date, full body and
   the JSON-LD `<script>` in raw SSR HTML (verified by reading `app/(site)/[category]/[slug]/
   page.tsx` + server components; no client-side injection of primary content). Error pages
   (not-found.tsx, error.tsx) are server-rendered.
2. **Status codes** — real 404 via `notFound()` on unknown article/category/tag/author slugs;
   category mismatch → `permanentRedirect` (301); maintenance → real **503** with Retry-After
   from `middleware.ts`; no soft-404 patterns found.
3. **URLs** — one canonical shape `/{category-slug}/{article-slug}`, lowercase-hyphenated slugs
   from `slugify_php`; no trailing slash generated anywhere; internal links built from the same
   slug fields as canonical/sitemaps (`canonicalArticlePath`, `articlePath`).
4. **Canonical tags** — exactly one per page, absolute, self-referencing by default; CMS-supplied
   canonicals validated against an origin allow-list server-side (`canonical_url_allowed()`).
5. **Meta robots** — index/follow defaults with per-article overrides surfaced from DB flags;
   unexpected metadata failures fall back to noindex rather than mis-indexing error states.
6. **robots.txt** — generated at `app/robots.ts`: explicit AI-bot policy (GPTBot/OAI-SearchBot/
   ClaudeBot/Claude-SearchBot/PerplexityBot allowed for content, admin+api blocked; CCBot/
   Bytespider/Ahrefs/Semrush et al. fully blocked), sitemap index + news sitemap referenced,
   host directive set. Matches the pass-1 policy (issue #84 regression fixed).
7. **Sitemaps** — `sitemap-index.xml` + segmented article sitemaps (1000/page) + taxonomy +
   static pages via `app/sitemap.ts`; news sitemap window configurable via
   `site_settings.news_sitemap_window_hours` (default 48h), capped at Google's 1000-entry limit,
   UTC-parsed dates, sorted newest-first; `<lastmod>` derived from the same DB timestamps used
   for JSON-LD datePublished/dateModified. CI runs a sitemap integrity job.
8. **Structured data** — `@graph` pattern: NewsArticle family (type resolved safely from
   content_type — HowTo/Review downgraded to Article to avoid Rich Results errors), Person author
   with bio URL + sameAs, NewsMediaOrganization publisher with logo, BreadcrumbList on articles/
   categories, WebSite+SearchAction and ItemList on home, Person/ProfilePage on author pages.
   JSON-LD emitted through XSS-safe serializer. og:image == JSON-LD image via shared
   `articleOgImage()`. **Fixed this pass:** feed + editors-picks dead image URLs (F2/F3).
9. **Performance** — ISR everywhere, GA4/GTM afterInteractive, hero eager + below-fold lazy,
   AVIF/WebP via next/image config, immutable caching for static assets, PHP-side 60s homepage
   cache, gzip/Brotli at edge. CWV field-data check remains a post-deploy operator task.
10. **Admin enforcement** — hard blocks live server-side in `article_policy.php`
    (`assert_publishable`) so UI bypass cannot publish without meta description, alt text,
    author, category; warnings (length ranges, small images, missing tags) surface in the editor
    with live counters and social preview (SEOPanel component).
11. **Content rules** — schema_type allow-list prevents invalid rich-result types; corrections
    flow exists (/corrections + policy); BLUF-style structure is editorial guidance.
12. **Security/server-level** — HTTPS forced + www canonicalization in `public/.htaccess`;
    HSTS 1y includeSubDomains; mixed-content safe (all asset helpers force https or same-origin);
    `.env/.sql/.log` denied at server level.
13. **Pre-merge checklist** — encoded in CI (build, tests, lint, php lint, sitemap job);
    Rich Results validation is manual pre-merge.
